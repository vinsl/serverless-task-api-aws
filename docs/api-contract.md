# Serverless Task API — API Contract

## Overview

- **Base URL:** Terraform output `api_endpoint`
- **Content type:** `application/json`
- **Architecture:** API Gateway HTTP API → AWS Lambda → DynamoDB
- **Authentication:** None in V1
- **API Gateway payload format:** 2.0

> Important: because V1 has no authentication, `author` is supplied by the client and must not be considered a verified identity. A future version should derive the author from a JWT/Cognito identity.

---

## Task model

A task stored in DynamoDB has this structure:

```json
{
  "taskId": "7e21be6b-4e88-4bd8-bb0f-8d1d64e5e2bb",
  "title": "Préparer entretien Cloud Engineer",
  "content": "Réviser IAM, Terraform et Lambda",
  "author": "vincent",
  "status": "todo",
  "createdAt": "2026-09-10T19:20:00+00:00",
  "updatedAt": "2026-09-10T19:20:00+00:00"
}
```

| Field | Type | Required | Description |
|---|---:|---:|---|
| `taskId` | string (UUID) | Yes | Unique task identifier generated by the API |
| `title` | string | Yes | Non-empty task title |
| `content` | string | Yes | Non-empty task content |
| `author` | string | Yes | Non-empty author name supplied by the client in V1 |
| `status` | string | Yes | One of `todo`, `in_progress`, or `done` |
| `createdAt` | string | Yes | UTC creation timestamp in ISO 8601 format |
| `updatedAt` | string | Yes | UTC last-update timestamp in ISO 8601 format |

## Endpoints

### Create a task

```http
POST /tasks
Content-Type: application/json
```

#### Request body

```json
{
  "title": "Préparer entretien Cloud Engineer",
  "content": "Réviser IAM, Terraform et Lambda",
  "author": "vincent"
}
```

#### Success response — `201 Created`

```json
{
  "taskId": "7e21be6b-4e88-4bd8-bb0f-8d1d64e5e2bb",
  "title": "Préparer entretien Cloud Engineer",
  "content": "Réviser IAM, Terraform et Lambda",
  "author": "vincent",
  "status": "todo",
  "createdAt": "2026-09-10T19:20:00+00:00",
  "updatedAt": "2026-09-10T19:20:00+00:00"
}
```

#### Validation rules

- `title` is required and must be a non-empty string.
- `content` is required and must be a non-empty string.
- `author` is required and must be a non-empty string.
- `status`, `taskId`, `createdAt`, and `updatedAt` are generated by the API.

### List tasks

```http
GET /tasks
```

#### Success response — `200 OK`

```json
{
  "items": [
    {
      "taskId": "7e21be6b-4e88-4bd8-bb0f-8d1d64e5e2bb",
      "title": "Préparer entretien Cloud Engineer",
      "content": "Réviser IAM, Terraform et Lambda",
      "author": "vincent",
      "status": "todo",
      "createdAt": "2026-09-10T19:20:00+00:00",
      "updatedAt": "2026-09-10T19:20:00+00:00"
    }
  ],
  "count": 1
}
```

An empty table returns:

```json
{
  "items": [],
  "count": 0
}
```

---

### Get one task

```http
GET /tasks/{taskId}
```

#### Success response — `200 OK`

Returns a single task object.

#### Not found response — `404 Not Found`

```json
{
  "error": "NotFound",
  "message": "Task not found"
}
```

---

### Update a task

```http
PATCH /tasks/{taskId}
Content-Type: application/json
```

#### Request body

At least one allowed field must be provided:

```json
{
  "title": "Préparer l'entretien AWS",
  "status": "in_progress"
}
```

#### Allowed update fields

- `title`: non-empty string
- `content`: non-empty string
- `status`: `todo`, `in_progress`, or `done`

The API updates `updatedAt` automatically. The fields `taskId`, `author`, and `createdAt` cannot be modified in V1.

#### Success response — `200 OK`

Returns the complete updated task object.

#### Not found response — `404 Not Found`

```json
{
  "error": "NotFound",
  "message": "Task not found"
}
```

---

### Delete a task

```http
DELETE /tasks/{taskId}
```

#### Success response — `204 No Content`

The response has no body.

#### Not found response — `404 Not Found`

```json
{
  "error": "NotFound",
  "message": "Task not found"
}
```

---

## Error format

All API errors use the following JSON structure:

```json
{
  "error": "ValidationError",
  "message": "Human-readable explanation"
}
```

| Status code | Error code | When it happens |
|---:|---|---|
| `400` | `ValidationError` | Missing body, invalid JSON, missing required field, empty field, invalid status, or no valid update field |
| `404` | `NotFound` | The requested route or task does not exist |
| `500` | `InternalServerError` | Lambda cannot complete an operation with DynamoDB or another unexpected server error |

## Examples

### Create a task

```bash
curl -X POST "$API_ENDPOINT/tasks" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Préparer entretien Cloud Engineer",
    "content": "Réviser IAM, Terraform et Lambda",
    "author": "vincent"
  }'
```

### List tasks

```bash
curl "$API_ENDPOINT/tasks"
```

### Get one task

```bash
curl "$API_ENDPOINT/tasks/<taskId>"
```

### Update a task

```bash
curl -X PATCH "$API_ENDPOINT/tasks/<taskId>" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "done"
  }'
```

### Delete a task

```bash
curl -X DELETE "$API_ENDPOINT/tasks/<taskId>"
```
